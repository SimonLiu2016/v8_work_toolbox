## Context

当前短剧 IP 主库中的场景（`SceneCard`）仅包含单一的 `descriptionZh`、`promptEn` 和 `imagePath`。在小说全案导入与分镜生成流程中，这一结构暴露出以下痛点：
1. **空间维度缺失**：仅有单一口径的描述，在正打、反打、仰视天花、俯瞰全景等不同机位镜头下，生图模型容易随机捏造背景，导致切镜穿帮。
2. **小说描述夹杂人物**：小说原著对场景的描写往往夹杂主角出场、恩怨叙事（如风月场所丽香苑“富家公子与江湖草莽在此交错”），AI 提取出的场景描述若不经纯净空间解构，生成的场景图极易携带路人与主角。
3. **缺乏多方位编辑与按需生图**：用户无法针对特定视角（如穹顶、地砖、反打入口）单独修改描述或单独生图，也缺少一键批处理推演工具。

详见 `proposal.md`。

## Goals / Non-Goals

**Goals:**
- **数据结构扩展**：在 `studio_models.dart` 中建立 `SceneDirection`（7 维度）与 `SceneDirectionalView` 模型，扩展 `SceneCard.spatialViews`，完全兼容旧数据序列化。
- **AI 空间约束引擎**：新增 `StudioAiTask.sceneSpatialDeconstruction` 任务，结合时代题材与世界观，强制推演 7 个纯物理空镜空间视角（中英文双语），确保材质采光一致且彻底过滤人物叙事。
- **两阶段触发与编辑**：小说导入时自动推演补全；场景库顶栏支持一键全量解构；场景编辑弹窗支持单场景推导与 7 方位独立修改。
- **按需与成套生图控制**：每个视角支持单独生图/绑定图片，编辑面板提供「一键生成全息组图」批量调度，严格禁止静默后台生图。
- **下游机位自适应匹配**：分镜与片段装配器（`PromptAssembler`）根据镜头机位（俯瞰/仰拍/反打/正打等）智能匹配对应方位的场景提示词与参考图。

**Non-Goals:**
- 不引入重型 3D 建模、点云重建或 Gaussian Splatting，保持轻量高效的 2D 多视角参考图矩阵体系。
- 不在解构推演阶段自动并发调用生图 API，仅生成文本与 Prompt，生图始终由用户显式触发。

## Decisions

### 1. 七方位几何坐标与语义映射定义
- 视角枚举 `SceneDirection`：
  - `front`（前 / 正面主景）：空间视觉核心，主案、屏风、神龛、主展示面。
  - `back`（后 / 反打背景）：进退通道，玄关大门、退路走廊、屏风后壁。
  - `left`（左 / 左侧立面）：采光主立面，排窗、落地窗、左侧副案或挂画。
  - `right`（右 / 右侧立面）：内室通道、侧席博古架、展示柜或帷幔。
  - `top`（上 / 天顶结构）：天花藻井、梁木结构、穹顶或吊灯管线。
  - `bottom`（下 / 地面铺装）：青砖地坪、木纹地板、织锦地毯或铺装纹理。
  - `topDown`（俯视 / 空间鸟瞰全景）：空间整体平面拓扑结构，长宽进深与陈设布局鸟瞰。
- 采用明确的枚举与固定的 Map 键名，序列化为纯字符串键值，便于跨平台存储与 JSON 直读。

### 2. 模型层平滑向后兼容策略
- `SceneCard` 新增 `spatialViews: Map<String, SceneDirectionalView>` 字段。
- 在 `SceneCard.fromJson` 反序列化时：
  - 若 `spatialViews` 为空，自动初始化 7 个空方位视图，其中 `front` 自动以现有的 `descriptionZh`、`promptEn`、`imagePath` 填充。
- `SceneCard.imagePath` 和 `SceneCard.promptEn` 继续作为主视图（`front`）的快捷别名，保证未适配此特性的现有代码不受影响。

### 3. AI 约束引擎推演机制 (`StudioAiTask.sceneSpatialDeconstruction`)
- 输入上下文：
  - `eraGenre`（如“盛唐古风 / 仙侠修真 / 现代商战”）；
  - `visualStyle`（制作风格与材质基调）；
  - `sceneName`（场景名称）；
  - `baseDescription`（小说提取出的原始环境片段）。
- 硬约束提示词：
  - 严禁人物：彻底剔除一切人物登场、活动、对话与剧情冲突，仅保留空镜空间与物理陈设；
  - 材质与光影自洽：定义统一主光源位置（例如“光线自左侧排窗洒入”），各立面与天顶地坪的明暗、投影方向与建筑形制保持严格几何对应；
  - 严格 JSON 键名输出：返回 7 个视角的 `zh` 与 `en` 对象。

### 4. UI 交互架构与视觉规范
- **场景库顶栏**：新增「一键全息解构全部场景」操作项，带清晰进度弹窗与跳过已解构项逻辑。
- **`_SceneEditorSheet` 编辑弹窗重构**：
  - 顶部操作栏：展示场景基本信息，右侧提供「AI 全息解构七方位」与「一键生成全息组图 (7视角)」操作；
  - 方位视口面板：提供 7 方位快速切换 Tab 或紧凑网格视图，每个视角包含：
    - 视角标签（如：`正面主景 (Front)`、`天顶结构 (Top)`）；
    - 视角缩略参考图（支持点击放大、按需生成、选择本地图片、清除图片）；
    - 中文空间描述 TextField（支持多行编辑）；
    - 英文生图 Prompt TextField（支持多行编辑）；
    - 独立的「生成此视角图片」快捷按钮。

### 5. 下游消费：机位自适应匹配算法
- 在 `PromptAssembler` 与 `SegmentVideoGenTask` 中：
  - 分析 `StoryboardShot.cameraAngle` / `cameraMovement` / `shotType`：
    - `low angle` / `仰拍` / `仰视` -> 命中 `top` 视角；
    - `high angle` / `bird eye` / `俯拍` / `俯瞰` / `远景鸟瞰` -> 命中 `topDown` 视角；
    - `reverse` / `反打` / `过肩反打` / `背向` -> 命中 `back` 视角；
    - `left` / `左移` / `向左看` -> 命中 `left` 视角；
    - `right` / `右移` / `向右看` -> 命中 `right` 视角；
    - `ground level` / `贴地` / `地面特写` -> 命中 `bottom` 视角；
    - 其余默认或特写镜头 -> 命中 `front` 视角。
  - 若命中方位的 `imagePath` 存在，优先将其作为该分镜的场景视觉参考图；若命中方位的 `promptEn` 存在，将其合并至分镜环境 Prompt，提升镜头画面的空间逻辑统一性。

## Risks / Trade-offs

- **[Risk 1] 小说文本夹杂大量打斗与对话，AI 推演可能残留人物痕迹**
  - *Mitigation*：在 System Prompt 中设置零容忍负向约束，并在 AI 返回结果解析时执行纯净度过滤正则检查，若发现角色代词触发二次清洗。
- **[Risk 2] 一键生成 7 方位组图并发消耗过大，生图配额超限**
  - *Mitigation*：默认不自动生图；一键生成组图时弹出耗额确认提示，通过任务队列串行/受控并发调度，避免触发云端服务速率限制。
- **[Risk 3] 7 个视角描述在小屏幕上信息量密集，编辑体验拥挤**
  - *Mitigation*：在 `_SceneEditorSheet` 中采用「方位导航侧栏/Tab + 聚焦视口详情编辑区」的联动响应式布局，保证单视口编辑专注且视野清晰。
