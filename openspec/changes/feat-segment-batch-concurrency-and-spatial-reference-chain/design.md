## Context

AI 视频工坊以连续剧（Series）为核心管理单元，在制作分镜看板（`StoryboardBoard`）中将分镜组织为大段（`StudioSegment`）。大段在视频模型中作为连续镜头生成的最小叙事单元，而单镜头（`StudioShot`）负责关键帧与细节镜头描述。当前分镜看板对大段的生成控制处于初级阶段，缺少成片播放、一键批量入队以及并发与时长控制。

在场景资产库（`_ScenesTab`）中，七方位空间全息负责提供 3D 纯净空镜视角（前、后、左、右、顶、俯、仰），由于当前生图逻辑将所有已生成的全息方位图片混入场景通用参考图池（`_refs`），导致后续视角横向受到前序视角的严重带偏（如右侧视角受到左侧视角的构图与元素污染）。

在跨剧资产库（`AssetLibraryPage`）中，视频资产存在缩略图死黑无画面、缺失创建时间显示、名称无法重命名以及分类修改入口隐蔽且与整卡手势冲突等操作痛点。

## Goals / Non-Goals

**Goals:**
1. **大段就地循环播放**：在大段卡片上提供就地播放预览与 Finder 定位能力，无须收进资产库即可检查成片。
2. **一键批量调度与并发控制**：提供一键生成全集所有大段功能，并在任务队列抽屉及设置中提供 1~5 并发数动态调节与持久化。
3. **大段目标时长交互式配置**：解除 12s 硬编码，支持在卡片上自由切换常用时长（5s/8s/10s/12s/15s）或自定义输入。
4. **七方位参考图隔离与方案 B 自定义链**：非正面方位默认仅继承正面主景（Anchor）与基础概念图，彻底隔离其他侧向视角；并在界面提供参考源勾选器供用户按需配置。
5. **资产库视频封面与信息编辑**：为视频资产提供海报帧展示（告别纯黑方块）、呈现创建时间、支持修改资产名称与统一编辑分类。

**Non-Goals:**
- 不重构底层视频模型推理引擎或引入新的外部视频播放插件（沿用现有 `media_kit` 与 `StudioTaskQueue`）。
- 不破坏现有分集剧本（`StudioEpisode`）与场景模型（`SceneCard`）及资产库索引（`assets.json`）的向下兼容性。

## Decisions

### 1. 媒体播放弹窗泛化（`_MediaPreviewDialog` 抽象）
- **方案选择**：将 `_MediaPreviewDialog` 改造为支持泛型媒体载体（接受媒体文件、缩略图、标题、副标题与分镜/大段元信息）。
- **理由**：单镜头与大段生成的视频都是标准的本地 MP4 文件，播放控制（循环播放、宽高比自适应、音画同步、Finder 揭示）逻辑完全一致，统一弹窗可避免重复编写 `Player` 与 `VideoController` 生命周期管理代码。
- **替代方案**：单独编写 `_SegmentPreviewDialog`。缺点：代码冗余度高，后续播放器手势或快捷键优化需维护双份。

### 2. 任务队列并发数持久化与动态生效
- **方案选择**：
  - 在 `SettingsStore` / 本地偏好中持久化 `studio_task_max_concurrency`（默认 2，取值范围 1~5）；
  - `StudioTaskQueue.instance` 初始化及用户在 UI 调整时调用 `setMaxConcurrency(val)` 并保存到本地存储；
  - 任务队列抽屉（`_QueueDrawer`）顶栏增加紧凑型并发数调节组件。
- **理由**：云端视频模型（如 SenseAudio、Kling 等）的 API 限流因用户账号权限而异，将并发数配置权交还给用户，既能保证普通用户的稳定不超限，又能让高配额用户全速并发产出。

### 3. 一键批量生成大段任务与幂等保护
- **方案选择**：
  - 看板顶栏新增 `[一键生成所有大段]` 按钮；
  - 弹窗展示预检信息：总片段数、待生成片段数、已生成片段数；
  - 提供单选/复选：“跳过已有成片的大段（默认）”与“覆盖重新生成”；
  - 批量提交时，对已在队列中处于非终态（`queued` / `running`）的大段自动去重，避免重复提交相同任务。

### 4. 大段时长交互式配置与吸附通知
- **方案选择**：
  - 将 `_SegmentCard` 头部的时长文字升级为点击交互区（`InkWell`），点击呼出常用时长菜单（`[5s]`、`[8s]`、`[10s]`、`[12s]`、`[15s]` 及自定义秒数输入）；
  - 选中后更新 `segment.copyWith(targetDurationSec: sec)` 并触发 `_manager.saveEpisode` 即时保存；
  - 若用户请求时长超出当前配置视频模型的支持上限，模型适配层的能力吸附机制将在卡片上显示调整提示（如 `15s → 12s`），与现有行为保持一致。

### 5. 七方位参考图抗污染与方案 B（基准正面锚点 + 界面勾选控制）
- **核心架构**：
  ```
                     ┌────────────────────────────────────┐
                     │    场景原始概念图 (Base Concept)    │
                     └─────────────────┬──────────────────┘
                                       │
                                       ▼
                     ┌────────────────────────────────────┐
                     │    【正面主景】(Visual Anchor)      │
                     └─────────────────┬──────────────────┘
                                       │ (唯一的单向材质/色调锚点)
         ┌────────────────┬────────────┼────────────┬────────────────┐
         ▼                ▼            ▼            ▼                ▼
   ┌───────────┐    ┌───────────┐┌───────────┐┌───────────┐    ┌───────────┐
   │ 【左侧面】 │    │ 【右侧面】 ││ 【反打背】 ││ 【顶视俯】 │    │ 【仰视底】 │
   └───────────┘    └───────────┘└───────────┘└───────────┘    └───────────┘
         ▲                ▲            ▲            ▲                ▲
         │                │            │            │                │
         └── 🚫 严禁横向参考 ┴────────────┴────────────┴────────────────┘
  ```
- **生图参考解析算法**：
  - 在 `series_page.dart` 中实现 `resolveSpatialReferences(SceneDirection dir, {Set<String>? userSelectedPaths})`：
  - **默认规则（方案 B 默认态）**：
    - 若生成 `front`：参考图仅取用户上传的场景基准概念图（非 `spatial_*.png`）；
    - 若生成非 `front`：参考图仅取“基准概念图” + “正面主景图”（`spatialViews['front']?.imagePath`），彻底剔除其它非正面视角；
  - **用户自定义规则（方案 B 交互态）**：
    - 界面提供候选参考图芯片：列出基础概念图、正面锚点与已生成的其他方位；
    - 用户若手动勾选/取消勾选，则严格按照用户选中的列表作为生图参考图；
  - **数据解耦**：
    - 方位生成成功后，仅写盘并回填至 `spatialViews[dir].imagePath`，**不再调用 `_refs.add(...)`**，杜绝全局图库的隐式膨胀与污染。

### 6. 视频资产封面海报帧绑定与降级渲染
- **方案选择**：
  - 在 `StudioAsset` 引入可空 `coverPath` 属性；
  - 入库时，若是从分镜（`_ShotCard`）或大段（`_SegmentCard`）收入，自动将对应的分镜关键帧（`frameFile`）复制并记录为 `coverPath`；
  - 若无关键帧（如用户直接导入本地 MP4），且系统检测到可用 FFmpeg，后台自动截取首帧另存为海报图片；
  - 在 `_AssetCard` 中，若 `asset.coverFile` 存在且有效，渲染 `Image.file(asset.coverFile!, fit: BoxFit.cover)`，其上覆盖半透明居中播放按钮与时长；若无封面，采用影视胶卷纹理微渐变卡片渲染，彻底杜绝纯黑死方块。

### 7. 资产信息统一编辑对话框（重命名与分类维护）
- **方案选择**：
  - 在 `StudioAsset` 中增加 `name` 字段；`AssetLibrary` 提供 `updateAsset(String id, {String? name, AssetCategory? category, String? note})` 方法；
  - 在 `_AssetCard` 底部操作栏新增 `[✏️ 编辑信息]` 操作按钮；
  - 点击弹出统一对话框：展示资产 ID、格式化的创建时间（`yyyy-MM-dd HH:mm`），并提供【资产名称】输入框、【所属分类】选择菜单（角色/场景/道具/关键帧/视频片段/其他）与【备注】输入框；
  - 保存后即时写盘并局部更新，页面无须重新拉取即可动态刷新。

## Risks / Trade-offs

- **[并发过高导致 429 限流]** → 缓解：并发上限严格锁死在 1~5，且任务底层已接入指数退避与抖动重试机制（Task 1），即使偶发 429 也会平滑等待重试。
- **[非正面视角未先生成正面]** → 缓解：若用户直接生成“右侧面”但“正面主景”尚未生成，系统退化为仅以“基础概念图”作为参考，并在界面提示建议先生成正面主景以获得最佳材质连贯性。
- **[多任务同时修改剧本数据竞争]** → 缓解：每个大段生成完成后仅局部更新该大段自身的 `clipPath` 与状态，并通过统一文件锁与主线程安全通知回写剧本。
- **[历史资产缺少海报封面图]** → 缓解：旧版本已入库的视频资产其 `coverPath` 为 null，卡片展示影视胶卷渐变纹理与居中播放按钮，并可在首次播放或编辑时自动补齐首帧缓存，不破坏旧数据。
