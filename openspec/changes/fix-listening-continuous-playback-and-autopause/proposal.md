# Change Proposal: 修复听力练习连续播放失效与句间停顿隐式残留问题 (fix-listening-continuous-playback-and-autopause)

## 1. 背景与问题陈述 (Context & Problem)
用户在“听力练习”模块中反馈：
1. **每句自动暂停且无法持续播放**：播放音频时，系统读完当前句子就会自动暂停，用户必须不断手动点击播放才能继续，无法保持整段或整首连续收听。
2. **“连续播放”按钮点击无效/产生误解**：右侧底部播放栏中的“连续播放（场景内循环）”按钮，点击后并未解决句末暂停的问题，且交互无明显感知反馈。

### 根因分析：
1. **`_autoPause` 状态跨曲目隐式残留**：
   `ListeningPlayerController` 中设置了 `_autoPause` 标志（原本用于影子跟读精听模式下的句末自动暂停复述）。当用户在精听/会议场景触发或开启过该机制后，即使切换音频片段（`play(clip)`）或切换到“公开素材”，`_autoPause` 依然保持 `true`。播放器监听器在检测到 `pos >= turn.endMs` 时强制调用了 `pause()`。
2. **控制栏按钮概念混淆与 UI 孤岛**：
   - 底部播放条的 `player.setContinuous` 实际控制的是“曲目列表连播（当前音频播放完后是否自动切到下一首）”，文案“连续播放（场景内循环）”让用户误以为是“取消单句暂停、持续畅听整篇”。
   - 控制 `_autoPause` 的开关原先仅在 `isMeeting && !player.isLoopingTurn` 下以“跟读停顿”出现；当用户进入公开素材库（`isMeeting == false`）时，该开关被彻底隐藏。用户既看不到为何被暂停，也无法将其关闭。

## 2. 变更目标 (Objectives)
1. **生命周期彻底重置**：切换不同音频片段（`play(clip)`）或重新加载会话时，默认重置 `_autoPause = false`，杜绝句间暂停残留至其他音频或公开素材。
2. **概念解耦与文案明确**：
   - 将原列表循环开关文案从“连续播放（场景内循环）”优化为更精准的“自动连播下一条（列表循环）”，明确其职责是曲目流转。
3. **全局状态显式化与快捷解除**：
   - 无论处于会议场景还是公开素材场景，一旦检测到 `isAutoPause == true`（句间停顿激活），在底部播放条展示鲜明且醒目的胶囊提示（如 `[⏸ 句间停顿跟读中 | 点击恢复连播]`）。
   - 用户只需点击该胶囊，即可直接关闭句间停顿，即刻恢复连续畅听。
4. **提升测试覆盖率**：针对生命周期重置与控制条交互补充自动化测试。
