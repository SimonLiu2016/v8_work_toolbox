# settings-storage Delta

## MODIFIED Requirements

### Requirement: 工具合并时的配置继承

当两个工具合并为单一工具时，被移除工具的既有配置 MUST 被迁移到承接工具的读取路径，且迁移 MUST 遵循与旧配置迁移一致的语义：复制而非移动，原文件保留不删除，只执行一次，不覆盖用户在承接键中的后续修改。未执行迁移即静默丢弃被移除工具的配置是不允许的。承接工具 MUST 在功能上读取迁移后的数据，使迁移不仅是数据搬迁而是用户数据的持续可用。

继承条件 MUST NOT 以"承接键当前为空"为前置。承接键已有内容（例如用户手动添加过条目）时，被移除工具的条目仍 MUST 被并入——按值去重合并，保留用户既有条目，不删除、不覆盖、不排序重写。继承完成标志仅用于抑制一次性提示，MUST NOT 阻断补救性并入；既有已完成继承但承接键非空、导致被移除工具条目此前未被并入的用户，其配置 MUST 在下一次读取时自愈补齐。

#### Scenario: 构建产物清理配置被瘦身工具读取

- **WHEN** 用户曾在"清理构建产物"中登记过项目根 watchlist，之后该工具并入智能磁盘瘦身
- **THEN** 这些 watchlist 条目与产物类型开关出现在瘦身工具的额外项目根配置中，且可作为产物发现阶段的补充输入

#### Scenario: 配置继承不覆盖用户新设置

- **WHEN** 用户在瘦身工具的额外项目根配置中做过修改后再次启动应用
- **THEN** 以瘦身工具的配置为准，被移除工具的配置内容不再被重复搬入，但用户既有条目保持原样不被删除或覆盖

#### Scenario: 被移除工具的原配置文件保留

- **WHEN** 配置继承执行完成
- **THEN** 被移除工具的原配置文件在统一存储中保持原样不被删除，以便回滚

#### Scenario: 承接键非空时仍并入被移除工具的条目

- **WHEN** 用户已在瘦身工具的额外项目根配置中手动添加过条目，而被移除工具的配置中另有未并入的条目
- **THEN** 被移除工具的条目按值去重并入，用户既有条目全部保留，不出现静默丢弃

#### Scenario: 已完成继承标志不阻断补救性并入

- **WHEN** 配置继承的完成标志已置位，但承接键当时非空导致被移除工具的条目此前未被并入
- **THEN** 下一次读取配置时被移除工具的条目被补齐并入，用户的配置自动恢复完整，无需手工修复
