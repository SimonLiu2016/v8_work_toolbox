# network-proxy Delta

## Purpose

为应用提供统一的应用级网络出口控制，使用户在网络需要中转的环境下能够显式声明代理通道，并确保所有内部 HTTP 请求与外部子进程都遵守同一通道策略。

## ADDED Requirements

### Requirement: 显式代理通道配置
应用 SHALL 允许用户配置一个应用级 HTTP(S) 代理地址（主机与端口），并在 AI 基础设施配置界面中提供该设置的持久化入口。未配置时应用 SHALL 保持直连行为。

#### Scenario: 配置代理地址
- **WHEN** 用户在配置界面填写代理主机与端口并保存
- **THEN** 该配置被持久化，并在应用下次启动后仍然生效

#### Scenario: 清除代理配置后恢复直连
- **WHEN** 用户清空代理配置并保存
- **THEN** 应用恢复直连行为
- **AND** 本次配置变更不影响其他已有的 AI 配置项

#### Scenario: 代理地址格式非法
- **WHEN** 用户输入无法解析为主机与端口的代理地址并尝试保存
- **THEN** 应用阻止保存并提示格式要求
- **AND** 此前生效的配置保持不变

### Requirement: 统一 HTTP 出口
应用内所有出站 HTTP 请求 SHALL 通过单一受控出口发出，使得代理策略在一次实现中即可覆盖全部网络路径，而非分散在各业务模块中各自处理。

#### Scenario: 已配置代理时全部请求经代理发出
- **WHEN** 代理已配置，应用内的 AI 对话、语音合成、文档解析等模块发起网络请求
- **THEN** 所有出站请求均经该代理通道发出
- **AND** 应用不遗留绕开统一出口的网络调用

#### Scenario: 未配置代理时行为与现状一致
- **WHEN** 代理未配置
- **THEN** 各模块的网络请求行为与引入统一出口之前完全一致，不产生新的失败模式

#### Scenario: 代理本身不可达
- **WHEN** 代理地址不可达
- **THEN** 受影响模块返回可诊断的连接错误，而非无限期挂起

### Requirement: 代理策略透传至外部子进程
应用通过 stdio 启动的外部子进程（MCP 客户端等）SHALL 继承与应用 HTTP 出口一致的代理策略，避免应用内部请求走代理而子进程请求绕过代理造成通道不一致。

#### Scenario: 子进程继承代理环境变量
- **WHEN** 代理已配置，应用启动一个 stdio 外部子进程
- **THEN** 该子进程的环境中包含与应用出口策略一致的标准代理变量
- **AND** 子进程发起的远端请求与应用内部请求走同一通道

#### Scenario: 未配置代理时子进程环境不含代理变量
- **WHEN** 代理未配置
- **THEN** 启动的子进程环境中不注入应用自造的代理变量
- **AND** 不覆盖用户环境中原有的代理设置

### Requirement: 通道可用性可自诊断
应用 SHALL 在配置界面提供代理通道可用性检测，使用户能够区分「代理未配置」「代理不可达」与「远端服务故障」三种不同的失败原因。

#### Scenario: 检测代理通道
- **WHEN** 用户在配置界面执行代理通道检测
- **THEN** 应用报告该通道是否可建立连接，以及是否可用于访问目标站点
- **AND** 失败时给出可区分的失败原因，而非笼统的网络错误
