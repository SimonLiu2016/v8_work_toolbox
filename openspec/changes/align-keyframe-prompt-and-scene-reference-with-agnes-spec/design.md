## Context

当前系统在关键帧生成时存在两层严重缺陷：
1. UI 调用链路 (`StoryboardBoard._enqueueFrame`) 遗漏了 `scene` 参数，导致 `ImageGenTask` 未将大牢等场景图作为参考图提交给生图模型。
2. 提示词组装引擎 (`PromptAssembler`) 沿用旧版西文扩散模型的 `promptEn` 模式与 Tag 堆叠逻辑，完全未遵循 Agnes Image 2.5 Flash 官方文档中要求的自然语言多图合成与信息密度分层规范，且全局画风硬编码的“云海雾气”严重污染室内场景。

## Goals / Non-Goals

**Goals:**
- 在分镜关键帧生成全流程中自动解析并注入 `SceneCard` 及其最佳机位空间参考图（如 `spatial_front`）。
- 废弃对 `promptEn` 的单一依赖，全面提取场景与空间档案的详尽中文物理描写（`descriptionZh`）。
- 严格按照 Agnes Image 2.5 Flash 官方规范重构提示词装配管线：
  - 多图模式自动注入 `[参考图角色与保留声明]`（如“将第一张图作为主要角色姜七夜，第二张图作为次要角色老王，第三张图作为背景场景参考巡城司大牢值房...”）；
  - 主体核心动作与戏剧焦点置顶前置，确保高注意力权重；
  - 角色文字描述精简锚点化，避免用数百字立绘文字冲淡动作与环境；
  - 场景室内/室外自适应净化，彻底消除地下水牢/室内场景中的“云海雾气”污染。

**Non-Goals:**
- 不重写视频生成 (I2V) 协议逻辑（保留原有首尾帧接力规范）。
- 不破坏对其他无参考图模型（如本地占位图或纯文生图）的兼容回退。

## Decisions

### 1. 场景卡与空间参考图的双重兜底注入
- **UI 触发端显式传递**：在 `StoryboardBoard._enqueueFrame` 中按 `shot.sceneId` 从 `_scenes` 中找出对应的 `SceneCard` 并传入 `ImageGenTask(scene: matchedScene)`。
- **任务执行端防漏兜底**：在 `ImageGenTask.run` 中，若 `scene == null` 但 `shot.sceneId.isNotEmpty`，自动通过 `StudioProjectManager.instance.readSceneCard(seriesId, shot.sceneId)` 自动反查并补全，杜绝未来任何入口漏传。
- **参考图序列契约**：按照 `[主要角色立绘, 次要角色立绘(如有), 场景空间主视图]` 的确定性顺序打包进入 `ImageGenRequest.referenceImages`。

### 2. 严格按 Agnes 官方规范设计多图自然语言提示词架构
Agnes 官方多图合成语法要求明确告诉模型每张图的职责与保留要素。提示词结构重构为 5 个核心段落：
```
┌────────────────────────────────────────────────────────────────────────┐
│ 段落 1: 多图角色与保留指令 (Multi-Image Role & Preservation Directive)   │
│ "将第1张图作为主要角色（姜七夜），第2张图作为次要角色（老王），        │
│  第3张图作为背景环境参考（巡城司大牢）。保留前述角色的面容身形与制服，  │
│  保留场景图中的粗木铁栏、旧木案与刑架空间布局。"                       │
├────────────────────────────────────────────────────────────────────────┤
│ 段落 2: 核心视觉动作与主体焦点 (Action & Dramatic Core - 前置高权重)   │
│ "【核心动作与焦点】: 姜七夜单手按在腰间刀柄，手指轻敲刀鞘，神态不羁... │
│  老王立于案侧，怒容满面指责训斥。"                                     │
├────────────────────────────────────────────────────────────────────────┤
│ 段落 3: 场景环境与物理空间 (Scene Environment - 来自 descriptionZh)     │
│ "【场景环境】: 巡城司大牢值房，青石条地面泛着水光，粗木铁栏向暗处延伸，│
│  柏木旧案上摆放泛黄囚册与油灯，刑架悬挂锈蚀铁链..."                   │
├────────────────────────────────────────────────────────────────────────┤
│ 段落 4: 光照与氛围自适应 (Lighting & Atmosphere)                       │
│ "【光影氛围】: 昏暗油灯暖黄微光，铁栏投下森冷栅影，阴冷潮湿质感。"     │
├────────────────────────────────────────────────────────────────────────┤
│ 段落 5: 构图与画质规范 (Composition & Quality Baseline)               │
│ "中近景构图，微景深，次世代 3D 国漫写实风格，高视觉密度，超高细节。"   │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 场景室内/室外自适应净化机制
- 通过 `scene.setting == '内景'`，或者场景名称与描述命中室内/地下关键词（如 `牢, 水牢, 狱, 房, 室内, 密室, 殿, 堂, 窟, 洞, 阁, 廊`）进行判断。
- 若判定为封闭室内/地下场景，在过滤画风基线词时自动剥离 `云海, 雾气, 苍穹, 天空, 日出, 日落, 晚霞, 广阔天地, 宏大远景` 等互斥词，注入 `室内局部光照, 幽暗环境微光`，从根本上解决大牢变山巅的荒谬现象。

## Risks / Trade-offs

- **[Risk] 部分历史自建场景没有 spatial_views 空间档案**  
  → **Mitigation**: 优先使用匹配机位的 `spatial_views`；若无，降级使用 `scene.referenceImages.first`；若依然无图片，优雅降级为纯自然语言环境描述，并在 Prompt 中明确说明为文生图描述。
- **[Risk] Prompt 长度超过某些后端 Token 上限**  
  → **Mitigation**: 精简角色文本描述，三视图已有面容与衣服信息，文字中仅保留角色名与核心特征标签；总 Prompt 仍受 `PromptAssembler._joinWithinLimit` 750 词上限守卫。
