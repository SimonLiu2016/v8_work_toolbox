## Context

当前局域网扫描分为「阶段 1：存活发现」与「阶段 2：端口深度扫描」。
在 macOS 普通桌面用户权限下，阶段 1 调用的 `arp-scan` 因访问 `/dev/bpf` 权限被拒静默失败；回落的 `nmap -sn -PR` 因非 root 静默退化为非特权 TCP Connect Ping（仅测 80 与 443 端口），导致关闭该端口的局域网终端（如手机、平板）被误判为离线，阶段 2 仅能扫描本机。详细背景见 `proposal.md`。

## Goals / Non-Goals

**Goals:**
- 实现免 Root、跨防火墙、高并发的局域网存活发现：利用 UDP 广播/多端口扇出激发 macOS/Linux 系统内核 ARP 请求，并读取系统原生 `arp -a` 缓存表。
- 100% 提取目标网段所有在线主机的真实 IP、MAC 地址，并基于现有 OUI 规则推断厂商。
- 优化 `ArpScanService` 策略链条：UDP 激发 + 内核 ARP 缓存优先；支持 nmap 多协议存活 Ping 补充；修复并规范 `arp-scan` 调用。
- 保证整个过程耗时控制在 1~2 秒内，不阻碍后续服务与端口扫描。

**Non-Goals:**
- 不强制通过 `sudo` 或 AppleScript 弹窗索要 root 密码（保持免密码平滑体验）。
- 不改动阶段 2（`NmapService.scan`）的端口与服务枚举核心逻辑，仅确保其输入完整的存活主机列表。

## Decisions

### 1. 采用「UDP 扇出激发 + 内核 ARP 解析」作为首选存活探测策略
- **原理**：使用 Dart 原生 `RawDatagramSocket` 并发向网段内每个 IP（如 `192.168.1.1` ~ `192.168.1.254`）发送轻量 UDP 数据包（目标端口可为 NetBIOS 137、mDNS 5353 或 80）。无论目标操作系统是否开启防火墙或是否丢弃 UDP 包，目标主机的网络芯片/网卡固件都必须在以太网二层回复内核发送的 ARP Request（who-has）。
- **优势**：
  - 完全不需要 Root 或 `/dev/bpf` 权限；
  - 254 个 IP 的并发发送在 100~200ms 内完成，内核在 500ms 内完成 ARP 缓存更新；
  - 穿透目标主机操作系统防火墙；
  - 直接带出真实 MAC 地址。
- **替代方案对比**：
  - *方案 B: nmap 多端口 SYN/UDP Ping (`-PS... -PU...`)*：耗时长（20~40s），且仍会被目标静默防火墙丢包，无法获得 MAC。
  - *方案 C: 强制 sudo*：破坏桌面 App 易用性，并造成数据库文件权限污染。

### 2. 系统 ARP 命令（`arp -a` / `arp -an`）多平台健壮解析
- **命令适配**：在 macOS 上执行 `arp -an` 或 `arp -a`，解析形如 `? (192.168.1.1) at e8:12:2d:5f:22:f7 on en0 ...` 的行。
- **过滤逻辑**：
  - 过滤 `(incomplete)` 与广播地址（`ff:ff:ff:ff:ff:ff`）；
  - 严格限制匹配网段在用户指定的 CIDR 范围内（如 `192.168.1.0/24`）；
  - 提取规范格式的 MAC 地址（标准化为大写或小写冒号分隔）。

### 3. 多层优雅降级与融合逻辑
`ArpScanService.scan` 整体执行流水线：
1. **步骤 1**：执行 UDP 激发（快速发送探针）并等待 600ms；
2. **步骤 2**：读取系统 `arp -a` 解析当前网段的存活主机；
3. **步骤 3**：若解析到存活主机，直接产出结果（包含 IP、MAC 与厂商）；
4. **步骤 4**：若系统未返回有效主机（特殊环境限制），平滑降级执行 `nmap -sn -PE -PS22,80,443,8080,5000,7000 -PU53,137,5353` 补充探测并合并；
5. **步骤 5**：若安装了特权级 `arp-scan` 且用户明确配置，才可按需执行。

## Risks / Trade-offs

- **[局域网存在 AP 客户端隔离 (Client Isolation)]** → 某些极高安全等级的企业或访客 WiFi 会在路由器 AP 层面直接丢弃无线终端之间的二层转发（包括 ARP 与单播）。
  - *Mitigation*: 当 ARP 表仅有网关与本机时，通过多协议 Ping 与日志明确提示“若当前网络开启了 AP 隔离，无线终端之间可能不可见”。
- **[子网过大（如 /16）]** → 发送 65535 个 UDP 包可能导致短暂丢包或耗时增加。
  - *Mitigation*: 针对大于 /24 的网段进行批量分片限制（如每批 256 个，超时窗口控制）。
