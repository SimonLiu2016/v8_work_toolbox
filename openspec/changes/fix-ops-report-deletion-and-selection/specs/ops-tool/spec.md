## ADDED Requirements

### Requirement: 报告中心历史报告删除需二次确认与交互反馈

系统 SHALL 在用户点击历史报告列表项的删除操作时，提供破坏性操作的二次确认弹窗与明确的执行反馈，禁止静默物理删除。

#### Scenario: 弹出删除确认对话框
- **WHEN** 用户在报告中心左侧列表点击某份历史报告的删除图标
- **THEN** 系统 MUST 弹出包含该报告标题的确认对话框，告知该删除操作无法撤销
- **AND** 若用户点击取消，系统 MUST NOT 触发数据库删除，界面保持不变

#### Scenario: 确认删除后弹出提示反馈
- **WHEN** 用户在删除确认对话框中点击确定
- **THEN** 系统从数据库物理删除该份报告
- **AND** 系统通过底部 SnackBar 提示「报告已删除」

### Requirement: 删除报告后的选区退避与界面状态同步

系统 SHALL 在删除操作后正确同步左侧列表与右侧编辑/预览区的状态，防止已删除报告内容悬挂或选区丢失。

#### Scenario: 删除当前正在查看的唯一报告
- **WHEN** 历史报告列表中仅有 1 份报告且用户确认将其删除
- **THEN** 系统清空列表并展示「暂无历史报告」
- **AND** 系统将当前报告引用置空，清空标题与内容输入框，右侧区域展示「请选择或新建一份报告」空状态占位

#### Scenario: 删除当前正在查看的非唯一报告
- **WHEN** 历史报告列表中有多个报告，且用户删除了当前正在编辑或查看的报告
- **THEN** 系统自动将选区切换到剩余报告的第一项，并将右侧编辑区与预览区同步更新为该报告的标题与内容

#### Scenario: 删除未选中的其他报告
- **WHEN** 用户删除了历史列表中非当前选中的报告
- **THEN** 系统从列表中移除该项，右侧正在编辑的当前报告标题、内容与未保存修改保持不变

#### Scenario: 释放 Excel 生成跳转的初始报告挂载态
- **WHEN** 用户通过 Excel 模板生成报告并跳转至报告中心，随后执行了保存或删除操作
- **THEN** 系统释放初始挂载报告态，后续列表刷新或删除操作 MUST NOT 将当前选区强制还原为最初由 Excel 传入的对象

### Requirement: 报告 Markdown 正文内容持久化与还原

系统 SHALL 保证报告的 Markdown 内容或分节能够在本地数据库完整持久化，并在重新选中历史报告时完整恢复至编辑器与预览区。

#### Scenario: 保存并重新加载报告内容
- **WHEN** 用户在报告中心编写并保存报告，之后在左侧列表中重新点击该报告
- **THEN** 系统从数据库完整读取其 Markdown 正文内容并回填至文本控制器，Markdown 预览区正确渲染相应内容，不得出现内容变为空白
