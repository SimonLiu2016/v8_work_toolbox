## Context

当前 AI 短视频工坊直接从单集故事粗梗概（100~300 字）跳跃至 5D 分镜看板，缺失了影视工业核心的文学剧本（分场、对白、潜台词、动作节拍）阶段。在分镜与视频生成链路中存在以下几个严重的技术断点：
1. **视频提示词断层**：`VideoGenTask` 误将英文生图提示词（`assembledPrompt`）注入视频生成请求的 `promptZh`，导致台词（`dialogue`）与动作（`actionZh`）丢失，使得支持原生声画生成的大模型（如 Agnes Video）无法获知发声指令与对白文本。
2. **多角色同框截断**：`storyboard_board.dart` 与 `PromptParts` 仅截取 `shot.characterIds` 的第 1 个角色，丢弃了第二角色及其参考图（如余小白），导致多人互动镜头关键帧只剩单人。
3. **时长硬编码 4 秒**：`ai_constraint_engine.dart` 严格限制分镜时长在 3.0~5.0 秒，适配器层取整后钳制在固定 4 秒，无法匹配长台词或复杂微动作。
4. **复合动作超载**：单镜头挤压多个复合动作，导致物理生视频模型扭曲或动作跳跃。
5. **镜头间视听缺乏连续性**：前后镜头缺乏首尾帧接续、视线对位（180° 轴线）与动势继承。

技术与架构边界参见 `proposal.md` 与 `specs/`。

## Goals / Non-Goals

**Goals:**
- **剧本创作阶段落地**：新增 `screenplay` 独立工序，提供影视分场、角色对白、动作节拍编辑器，支持大纲/小说一键转剧本与剧本一键转分镜。
- **声画一体视频 Prompt 组装**：重构 `VideoGenTask` 提示词构建器，显式组装发声口令、角色对白、五维决策与微动作，激活原生音画同步与唇形匹配。
- **多角色同框参考图全量注入**：扩展 `PromptParts`、`ImageGenTask` 与 Agnes Image 适配器，支持多角色定位描述与多张参考图联合注入。
- **自适应动态时长（4~12s）**：重构 AI 约束规则与校验器，根据台词字数与动作节拍自适应计算镜头时长，适配 Agnes 4~12 秒原生能力。
- **复合动作过载拦截与智能拆镜**：在剧本与拆镜阶段限制单镜仅容纳单一/递进微动作，超载时自动拆解为连续镜头。
- **首尾帧接力与 180° 视线连续性**：支持前镜尾帧提取作为后镜首帧，并在连续性台账中维护视线朝向（`gazeDirection`）与轴线侧（`cameraAxis`）。
- **细化分镜看板生成状态**：解耦单镜重生成与大段批量生成的 UI 状态，避免单镜触发引起全局或多镜旋转加载。

**Non-Goals:**
- 引入端到端长视频自动剪辑大模型（仍以镜头级/片段级生图生视频为渲染基元）。
- 替换现有底层 SQLite/JSON 数据持久化架构（沿用 `StudioProjectManager` 文件系统序列化）。
- 实现自动语音识别（ASR）逆向对齐（当前阶段依赖模型原生声画合成或后续配音设计）。

## Decisions

### Decision 1: 独立「剧本工作台」工序与分场数据流模型
- **决定**：在 `StudioStage` 中在 `ideas` 与 `storyboard` 之间新增 `screenplay('screenplay', '剧本工作台', Icons.auto_stories_outlined)`，页面由 `ScreenplayPanel` 实现；剧本数据模型基于现有 `DramaScene` 与 `DramaBeat` 进行影视化扩展，保存在 `StudioEpisode.scenes` 中。
- **原因**：剧本是文本创作与戏剧逻辑的核心，与媒体生成密集型的「分镜看板」在视觉重心和交互模式上存在显著差异。独立工作台使用户可以专注打磨场次环境、角色潜台词与节拍对白，打磨完成后一键结构化转入分镜看板。
- **备选方案**：
  - *方案 A：在分镜看板顶部折叠剧本区域*：看板当前已包含 3500+ 行 UI 逻辑，包含分镜卡片、资产库抽屉、片段组、视频播放器，混合编辑剧本会导致页面过度拥挤。
  - *方案 B：纯 Markdown 纯文本编辑*：无法提供日夜景标签、角色绑定及静态动作复杂度校验等结构化约束能力。

### Decision 2: 视频生成专用 Prompt 组装器（声画全要素组装）
- **决定**：拆分生图 Prompt 与生视频 Prompt 的组装职责，在 `PromptAssembler` 中新增 `buildVideoGenPrompt(...)` 方法，视频提示词结构如下：
  1. 【环境与光影】：从 `DramaScene` 或五维决策提取光源方位、天气与质感；
  2. 【角色动作与物理动势】：提取 `actionZh` 及 `directorDecisions.physicalMomentum`；
  3. 【摄影运镜】：提取 `cameraMove` 及运镜轨迹；
  4. 【角色台词与发声指令】：提取 `shot.dialogue`，格式化为：`[对白发声]: 姜七夜大声说道：“余小白，我迟早得叫你姐夫！”（语气：戏谑，唇形同步对齐）`。
- **原因**：Agnes 等次世代视频大模型具备原生声画同步能力。若仅传入英文 Flux 生图词，模型缺乏角色对白语义与发声提示，导致人物哑剧且动作形变。
- **备选方案**：
  - *将台词英文翻译后放入英文 prompt*：中文台词翻译为英文后无法驱动精准的中文口型与发声发音，必须保留中文对话语义与标点。

### Decision 3: 多角色同框多参考图联合注入
- **决定**：
  1. 重构 `PromptParts`，将单角色 `CharacterCard? character` 升级为支持多角色 `List<CharacterCard> characters` 及对应的形态映射；
  2. 重构 `ImageGenTask._referenceImages`，收集当前分镜 `characterIds` 关联的所有角色面部/三视图，以及场景参考图；
  3. Agnes Image 适配器将所有参考图以公共 URL 或 Data URI 填入 `extra_body.image` 数组，并在提示词中明确空间相对位置（如：`Left side: 姜七夜...; Background 3rd floor: 余小白...`）。
- **原因**：影视分镜中对话与对抗场景通常为 2~3 人同框，硬编码截取第 1 个角色直接抹杀了配角的存在（如第 5 镜余小白消失）。
- **备选方案**：
  - *先分别生成两人，再通过本地画板拼合*：边缘融合与光影不一致风险极高，大幅增加用户手动操作成本。

### Decision 4: 动态时长自适应（4~12s）与复合动作拆镜保护
- **决定**：
  1. 解除 `ai_constraint_engine.dart` 中 3.0~5.0s 的硬约束校验，改为 `4.0 <= durationSec <= 12.0`；
  2. 时长预估公式：`duration = clamp(ceil(dialogue.length / 4.5) + actionPadding, 4, 12)`；
  3. 复合动作超载检测：在拆镜和剧本阶段，若检测到动作文本包含 3 个及以上连续复合动作短语，自动拆解为连续镜头（例如：特写撕鸡腿大嚼 -> 中景抬刀轻挑 -> 反打指三楼）。
- **原因**：物理生视频大模型单镜头无法承载多个前后因果断裂的动作。将复合动作拆解为视听递进镜头是影视镜头语言的标准做法，同时保证视频动作精准且时长自然。

### Decision 5: 首尾帧连续性接力与 180 度轴线维护
- **决定**：
  1. 在 `StudioShot` 中扩展 `firstFramePath` 与 `lastFramePath`，支持从前镜视频中通过 FFmpeg 自动抽离最后一帧；
  2. 在连续镜头（同场景未切出）视频生成时，将前镜的 `lastFrame` 作为后镜的 `first_frame` 提交；
  3. 在 `ContinuityLedger` 中记录 `gazeDirection`（视线方向）与 `cameraAxis`（轴线侧），确保对白正反打镜头视线相互对准（左看右 vs 右看左），防止跳轴。
- **原因**：视频片段拼接出现断层的主要原因是前一镜末尾与后一镜起点的肢体姿态与视线轴线不匹配。首尾帧接力与视线约束从根本上保证全集拼接的视听连贯。

### Decision 6: 分镜看板卡片操作与加载状态解耦
- **决定**：
  1. 隔离分镜看板中单镜重新生成与大段批量生成的通知范围，单镜重新生成时仅局部刷新该分镜卡片的生成进度与旋转指示器；
  2. 在 UI 上清晰区分「大段级批量连续渲染（用于片段视频拼接）」与「单镜微调重新生成」，避免产生功能冗余和误解。

## Risks / Trade-offs

- **[Risk] 多角色参考图同时提交可能导致生图模型注意力稀释或角色特征混淆**
  → **Mitigation**: 在提示词中显式标注角色空间定位与主客体对比（如 `Foreground Left: [姜七夜特征], Background Balcony: [余小白特征]`），并限制单镜头最多注入 3 位核心角色参考图。
- **[Risk] 首尾帧接续时若前镜末尾存在运动模糊，提取的尾帧可能影响后镜起始画质**
  → **Mitigation**: 提取前镜尾帧时提供质量阈值判定，若尾帧模糊，提供使用后镜关键帧或前镜倒数第 3~5 帧的容错回退机制。
- **[Risk] 4~12 秒长视频生成相较于 4 秒短视频消耗更多 API 额度与生成时间**
  → **Mitigation**: 在分镜看板卡片上直观显示预估时长与生成档位，并在设置中允许用户选择优先节省额度（保守 4~5 秒）还是优先沉浸体验（动态 4~12 秒）。

## Migration Plan

1. **数据模型向下兼容**：
   - `StudioEpisode` 中的 `scenes` 字段已有基础定义，新版本补充 `screenplayText` 及相关辅助字段时提供默认空值与老数据无缝加载。
   - `StudioShot` 中新增的 `firstFramePath`、`lastFramePath` 及连续性新字段均设为可空（`null`），旧分镜文件读取无需迁移脚本。
2. **渐进式生效**：
   - 用户打开已有剧集时，已拆好的分镜保持原样；当用户在分镜看板点击重新拆镜或在剧本工作台重新生成时，自动采用新的动态配时与多角色提示词组装逻辑。
