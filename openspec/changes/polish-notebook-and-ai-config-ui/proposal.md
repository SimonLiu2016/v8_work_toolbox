# Proposal: 笔记本与 AI 配置的界面打磨

## 背景与问题

实机使用「笔记本」与「AI 配置」时暴露三处界面问题：

### 1. 笔记详情的信息块散落，与元数据割裂

阶段一~三新增的三块内容（资产/凭证面板、AI 整理建议、关联笔记）被放在**编辑器格式工具栏之下**，而笔记的元数据（笔记本选择器、标签、置顶）在**工具栏之上**的元数据栏里。结果是同一篇笔记的属性信息被工具栏切成两段：

```
┌────────────────────────────────────────────┐
│ 标题                                        │
├────────────────────────────────────────────┤
│ 元数据栏 [📓▾] [#标签×] [+标签]        [📌] │ ← 属性在这里
├────────────────────────────────────────────┤
│ 格式工具栏          ← 把属性拦腰截断         │
├────────────────────────────────────────────┤
│ 资产 / 凭证 面板                            │ ← 属性又在这里
│ [AI 整理建议]                               │
│ 关联笔记 (N)                                │
├────────────────────────────────────────────┤
│ 编辑器画布（被上面三块挤压）                  │
└────────────────────────────────────────────┘
```

### 2. 笔记本浅色区域内的输入框看不清

应用全局主题是**暗色**，`app_theme.dart:169` 定义了 `inputDecorationTheme(filled: true, fillColor: bgInput=0xFF3C3C3C)`。笔记本是**浅色孤岛**——`note_editor.dart:467` 用浅色 `Theme` 包裹并显式覆盖 `filled: false` 来隔离。

新增的「问我的笔记」面板**没有做这个隔离**，于是深灰填充盖在其浅色容器上，叠加近黑字色，输入内容难以辨认。同类缺陷也存在于资产面板的「品类」输入框（嵌在浅灰面板里，较不显眼）。

### 3. API Key 只有遮蔽，没有查看途径

供应商编辑对话框的 Key 字段硬编码 `obscureText: true`——**恒为星号，且无任何开关**。编辑已有供应商时该字段为空（标签写着「已安全保存，若不修改请留空」），用户**完全无法确认当前存的是什么**，换机器或核对密钥时无从下手。

## 解决方案

三组独立修复：

**1. 元数据栏收拢属性入口**
把三块内容从工具栏之下**移入元数据栏**，与标签同排，形式对齐既有的 `[+ 标签]` 模式——紧凑 chip，点击开弹窗承载原有完整交互：

```
├────────────────────────────────────────────┤
│ 元数据栏 [📓▾] [#标签×] [+标签] [资产] [✨整理] [关联 N] [📌] │
├────────────────────────────────────────────┤
│ 格式工具栏                                  │
├────────────────────────────────────────────┤
│ 编辑器画布（不再被挤压）                     │
└────────────────────────────────────────────┘
```

- `[资产]` → 弹窗承载现资产面板全部编辑（品类/购买日/服务期/到期日/凭证勾选）；有资产数据时 chip 显示品类或到期倒计时
- `[✨整理]` → 现 AI 整理建议弹窗
- `[关联 N]` → 弹窗列出关联笔记（点击跳转 / 移除）；无关联时不显示该 chip
- 删掉原有的三块内联区域，把纵向空间还给编辑器

**2. 收紧浅色区域的输入框主题**
在「问我的笔记」面板与资产弹窗内统一做浅色 `Theme` 隔离（`filled: false, fillColor: transparent`），与 `note_editor` 的既有做法一致。**不用逐个 TextField 打补丁**——那正是造成本次遗漏的原因。

**3. API Key 默认遮蔽 + 眼睛可查看**
- 眼睛图标控制明/暗切换（常规交互）
- 编辑态下字段为空时，首次点击眼睛从密钥库读入已保存的密钥并显示，同时提示「已载入已保存的密钥」
- 载入仅用于**查看**：不触发重新写入密钥库；用户若不修改则保存时仍按"留空 = 保持原密钥"处理

## 能力（Capabilities）

**变更**
- `notebook-editor` — 笔记详情的属性入口收拢进元数据栏；浅色区域内表单字段的主题隔离要求。
- `notebook-knowledge` — 「问我的笔记」面板输入区可读性。
- `ai-configuration` — 供应商密钥字段默认遮蔽且可显式查看。

## 影响范围

- **修改**：`lib/tools/notebook/ui/note_editor.dart`（布局与 chip 化）、`asset_fields_panel.dart`（改为弹窗形态）、`related_notes_section.dart`（改为弹窗形态）、`notebook_qa_panel.dart`（主题隔离）、`lib/shell/ai_config_page.dart`（Key 字段眼睛图标 + 载入已存密钥）
- **新增**：可能抽出共享的浅色主题包装组件，供笔记本内多个浅色面板复用
- **无新增依赖**

## 非目标

- **不改暗色主题本身**。笔记本的浅色是刻意的（纸质编辑器观感），本次只修浅色区域内的串色。
- **不改资产/关联/AI 整理的功能语义**。仅搬动入口位置与呈现形态，底层服务与数据不变。
- **不改密钥存储格式**。眼睛图标只读展示，不改变 `KeychainService` 的写入路径。
- **不引入密码强度/密钥校验**。与本次打磨无关。

## 成功判据

1. 笔记详情页的元数据栏包含标签、资产、AI 整理、关联四类入口，且编辑器画布不被属性块挤压。
2. 「问我的笔记」输入框在浅色面板内文字清晰可读（无深灰填充）。
3. 编辑已有供应商时，点击 Key 字段的眼睛图标能查看已保存的密钥；默认仍为星号。
