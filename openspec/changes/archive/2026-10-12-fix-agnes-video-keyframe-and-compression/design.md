## Context

See proposal.md - Why.
Storyboard keyframe PNG images generated by the visual pipeline range from 1.0MB to 1.5MB. Converting raw PNG bytes to Base64 Data URIs yields ~1.88MB strings. Sending this in JSON to the New API proxy (`http://119.29.249.154:3356/v1/videos`) results in gateway truncation and upstream Agnes API returning `HTTP 400: keyframe 模式需要 first_frame 或 last_frame`. Furthermore, shared upstream channels frequently encounter `HTTP 429` rate limits.

## Goals / Non-Goals

**Goals:**
- Implement in-memory image pre-processing using the `image` package (already available in `pubspec.yaml`) to downscale input frames to 720P (maintaining aspect ratio) and compress to JPEG (quality ~85), keeping the byte size under 150KB.
- Ensure the resulting Base64 Data URI is safely under 200KB, eliminating gateway truncation.
- Support dynamic mode selection: `keyframe` when input image exists; `text` when no image exists.
- Implement exponential backoff retry for HTTP 429 ("当前分组上游负载已饱和") responses up to 4 attempts with progress updates.
- Keep Agnes video API payloads compliant with verified parameters (`model`, `prompt`, `mode`, `seconds`, `aspect_ratio`, and conditionally `first_frame`).

**Non-Goals:**
- Modifying image generation models or changing image resolution generated during keyframe generation.
- Changing disk storage format of generated keyframes (original PNG files remain on disk unmodified).

## Decisions

### Decision 1: Use `image` package to compress frames in-memory before Base64 encoding
- **Rationale**: `image: ^4.2.0` is already in `pubspec.yaml` and is cross-platform pure Dart. Downscaling to a maximum dimension of 1280px and encoding as JPEG quality 85 runs in under 50ms and reduces byte size from 1.4MB to ~120KB (~92% reduction).
- **Alternatives considered**:
  - *FFmpeg subprocess*: Unnecessary process spawn overhead; not all machines may have ffmpeg in path.
  - *Sending public COS URL*: While Agnes image returns COS URLs, users may upload local images or offline images where no public URL exists. Local compression works universally for all input images.

### Decision 2: Exponential backoff for HTTP 429
- **Rationale**: The New API proxy reports `429: 当前分组上游负载已饱和` due to transient upstream account saturation. Probing tests confirmed that channels recover after a few seconds. An exponential backoff (initial delay 2s, factor 1.5, max 4 retries) dramatically increases completion rate without user intervention.
- **Alternatives considered**:
  - *Failing immediately*: Forces the user to click "Generate Video" repeatedly in frustrating loops.

## Risks / Trade-offs

- [Risk: JPEG compression artifacts on keyframe input] → Mitigation: Quality 85 at 720P maintains crisp visual fidelity, perfectly matching the 720P resolution of `agnes-video-2.5-flash`.
- [Risk: Memory overhead during image decoding] → Mitigation: 1080x1920 RGBA image in memory is only ~8MB. Image buffer is immediately disposed after JPEG encoding.
