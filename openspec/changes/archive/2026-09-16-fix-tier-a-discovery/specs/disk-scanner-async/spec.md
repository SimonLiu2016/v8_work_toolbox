# disk-scanner-async Delta

## MODIFIED Requirements

### Requirement: 项目根发现的预算边界

项目构建产物扫描 MUST 以发现预算而非全盘遍历来界定工作量。浅层项目根发现层 MUST 在用户主目录下以有界深度 5 搜索构建清单信号，该层完成时间目标为秒级至十余秒级（本机实测剪枝后 depth 5 约 11s，覆盖 99.7% 真实根）；产物收集层 MUST 逐个项目根独立执行，并为每个根设定时间预算与产物数量预算。产物收集层 MUST 采用剪枝遍历：不下降进 `.git`、已命中的产物目录自身、以及不可回收的体积热点。浅层发现层 MUST 额外剪枝包管理器缓存目录（`.pub-cache`、`.npm`、`.yarn`、`.cache`、`.cargo`、`.rustup`、`.local`）与 `~/Applications`（后者仅在本阶段剪枝，不影响已卸载残留检测阶段）。MUST NOT 实现为对整个主目录的无界递归遍历。

#### Scenario: 浅层发现保持秒级至十余秒级

- **WHEN** 用户在主目录下存在数百个真实项目根
- **THEN** 浅层项目根发现层在十余秒内完成并返回候选根集合

#### Scenario: 主目录自身不作为项目根

- **WHEN** 用户主目录下直接存在构建清单信号文件（例如裸 `~/package.json`）
- **THEN** 主目录本身不作为项目根返回，其下已发现的其他项目根全部保留，不因去嵌套而消失

#### Scenario: 剪枝避免遍历产物本身与包缓存

- **WHEN** 产物收集层进入一个包含大量嵌套产物目录的项目根
- **THEN** 遍历不下降进 `.git` 与已命中的产物目录自身，单次遍历的已访问路径数受预算约束
- **AND** 浅层发现层不下降进包管理器缓存目录与 `~/Applications`

#### Scenario: 单根超预算降级为未完整

- **WHEN** 某个项目根的产物收集超过其时间预算
- **THEN** 该根停止收集并以"未完整"状态呈现已发现的部分，其余根继续扫描，扫描不因单个根超时而中断
