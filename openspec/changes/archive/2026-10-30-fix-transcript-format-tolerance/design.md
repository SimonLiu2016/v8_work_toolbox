## Context

见 `proposal.md - Why`。这里只记录决定方案形态的实测事实。

**语料实测**（`sea-doc` 仓库 30 份逐字稿）：

| 形态 | 平台 | 说话人行 | 二级标题 | 现解析器 |
|---|---|---|---|---|
| A | 钉钉 | `发言人 1 00:00:01` | 关键词 + 转文字 | ✓ |
| B | 豆包 | `@说话人 1  01:54` | **无** | ✗ |
| C | 钉钉（人名识别） | `李嘉成 00:00:03` | 关键词 + 转文字 | ✗ |
| D | 人工归档件 | 内嵌 A/B/C 之一 | 说明 + 原文 + 附录 | ✗ |
| E | 中英对照件 | `发言人 1 00:00:05` + 夹 `> 【译】` | 原文段 | ✗（译文会混入正文） |

现解析器有三道门槛（必须在 `## 转文字` 段内 / 必须「发言人」开头 / 必须 `HH:MM:SS`），分别把 B、C、D、E 挡掉。放宽到「整行结构判定」后，**30 份全部可解析，时间戳全部单调**。

## Goals / Non-Goals

**Goals:**

- 加一个新平台时不需要改解析器（形态差异落在数据里，而不是 if 分支里）
- 放宽格式之后，误判不会静默产出垃圾音频
- 合并说话人不破坏"原稿只读"

**Non-Goals:**

- 不做自适应学习（不记忆"上次这种文件怎么解析的"）
- 不做无时间戳形态（`张三：内容`）
- 不改续句合并、合成、词汇表的既有规则

## Decisions

### D1：整行结构判定，而不是扩充槽位名词白名单

判定条件：整行 = 可选前缀（`@` `#` `>` `-` `*` 与空白）+ 槽位名 + 可选序号 + 时间戳，行内无其他内容。

```
  @说话人 1  01:54        ✓  前缀 @ · 名 说话人 · 序号 1 · 时间
  发言人 2 00:00:21       ✓
  李嘉成 00:00:03         ✓
  Meeting at 10:30        ✗  名字后直接是 "at"，解析不成时间戳
  | 时间 | 2026-10-09 … | ✗  表格行被跳过
  see you at 10:30 tomorrow ✗ 行内有其他内容
```

**为什么不是白名单**：白名单每加一个平台就要改一次代码；而这四种形态的**共同结构**是"整行只有谁 + 什么时候"，白名单只是在给这个结构起名字。结构判定对新平台天然成立。

**代价**：任何"独占一行、形如 `X 10:30`"的行都会被当成说话人。靠 D2 的跳过规则 + D6 的单调校验 + D3 的预览兜住。

**备选**：让用户在导入时手动选平台（钉钉/豆包/其他）。否决——多一步操作，而且用户往往不知道自己的文件是哪个平台导出的。

### D2：全篇扫描，取消段落前置；`## 关键词` 降为可选

说话人行不再需要落在某个二级标题下面。二级标题只用于两件事：定位「关键词」段、判断是否为加工件。

扫描时跳过：
- ``` 围栏内的所有行（导出件把关键词放在代码块里）
- `>` 开头的行（元信息、`> 【译】…` 译文）
- `|` 开头的表格行

**为什么跳过 `>`**：中英对照件有 269 条 `> 【译】…` 紧跟在原文轮次之后。不跳的话译文会拼进这一轮正文，TTS 会把中英两版都念一遍——音频与文稿都对不上。

### D3：把「解析」与「落盘+合成」拆成两步

```
   现在： pick → parse → save → bake(152 次 TTS)
   之后： pick → parse → preview ─┬─ 取消 → 什么都不发生
                                  └─ 确认 → save → bake
```

`RealMeetingService.importFile` 拆成 `parseFile(path)`（返回预览模型）与 `commitImport(preview, onProgress)`。

**为什么必须拆**：放宽格式后，"解析成功"不再等价于"这是我要的那场会"。真按 D1 误判，代价是一条 20 分钟的假音频 + 152 次 TTS 调用。预览把判断权交回用户，成本是一次点击。

**备选**：解析后自动合成，错了再删。否决——"先烧钱再问"。

### D4：归档件识别用形态启发式，只标注不拒绝

判据（任一成立即标注为加工件）：
- 首个说话人行之前出现「原文」「转写」「记录」之外、且形如整理说明的二级标题（`## 说明`、`## 附录`、`## 原文（…）`）
- 文档在说话人行之外还含表格（`|`）且表格出现在首个说话人行之前

**为什么只标注不拒绝**：这类文件是用户手边最完整的版本（带说话人推定、术语校正）。拒绝会逼用户去翻附件，而附件不一定存在。

### D5：槽位合并 = 覆盖层里的 canonical 映射

`speaker_settings.json` 增加 `mergeInto: {槽位标识: 目标槽位标识}`。解析说话人时先做一次折叠：`effectiveSlot = mergeInto[slot] ?? slot`，之后显示名、音色、"是我"标记全部取目标槽位的设定。

**为什么放在覆盖层**：原稿的槽位标识是只读的（design D2 的既有约定）；合并是用户的解释，不是文稿的事实。取消合并 = 删掉一个映射项。

**代价**：合并后要重新合成被合并槽位的音频（音色变了）。这与"改音色"是同一条路径，复用 `_resynthesizeSlot`。

**备选**：物理合并槽位、改写原稿。否决——破坏"原稿只读"，且重新导入原件时会打架。

### D6：时间戳单调校验保留，并明确它同时是多会检测

现有校验是"任一轮时间早于前一轮 → 报错"。放宽格式后它多了一层职责：**一篇文档里嵌了两场会议时，第二场的时间戳会归零**，必然触发倒序，从而把"合并成一场假会议"挡在门外。

**代价**：真实逐字稿偶有轻微的说话人时间戳抖动（不同说话人的起算点略有差异）。当前语料 30 份全部单调，暂不做容差。

## Risks / Trade-offs

- **误认独占一行的 `X 10:30`** → 预览（D3）会把它显示成第一轮样例；单调校验拦下明显错误
- **译文/元信息漏跳**（新增 `>` 之外的引用形态）→ 预览展示前几轮原文，用户能立刻看出中英混排
- **合并后回答锚点** → 回答锚定在轮次下标，与槽位无关，合并不影响
- **关键词段缺失使噪声折叠更激进** → 预览里标注"未找到关键词段"，用户知道词表会更吵；折叠词仍可查（既有约束）
- **`录音时间：A - B` 的格式变体**（全角冒号、`至`、只给时长）→ 解析失败时回落为 0，不阻断导入；时长仅用于展示
- **归档顺序**：本 change 的 MODIFIED 依赖 `add-real-meeting-import` 归档后建立的 capability baseline，必须先归档它（见 proposal Impact）

## Migration Plan

已导入的会议不受影响：`meetingId` 由来源路径派生，解析规则变化不改变标识。用户重新导入同一文件时，若内容未变则无操作；若此前因格式报错而没导成，这次会正常走导入。

回滚：本次只改解析规则与新增 UI 流程，回滚代码即可；已落盘数据格式不变（`mergeInto` 是覆盖层里的新键，旧数据缺省为空映射）。
