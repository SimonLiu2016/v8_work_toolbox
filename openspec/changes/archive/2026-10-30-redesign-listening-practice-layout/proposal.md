## Why

「听力练习」先后叠加了三条内容管线——公开素材同步、会议材料排练、真实会议导入——但界面是按"功能加入的先后"一层层堆出来的：三条管线的入口分散在顶部工具栏、整行折叠面板、素材列表上方三个位置；"生成音频"有三个按钮且范围不清；类型 / 来源 / 场景三层筛选互相重叠；同一场会议有两套互不联动的"选中"；素材库为空时排练入口甚至不渲染。用户打开页面不知道该从哪里开始、该点哪个按钮。现在三条管线的功能都已到位，是时候按"用户要做什么"重新组织界面。

## What Changes

- 页面重构为**三栏 + 常驻播放条**：左侧资料库导航（「我的会议：真实会议 / 排练」与「公开素材：按场景」两个分区）、中间列表、右侧详情，底部固定全局播放条。
- 新增统一的**「＋ 新建」菜单**：导入真实会议逐字稿 / 新建排练 / 同步公开素材，替代分散的入口。
- **排练支持多场**：排练成为可列表管理的条目（新建、选择、重命名、删除），每场独立保存材料、讲稿、剧本、音频与目标时长。
- 排练详情改为**横向步骤条**（材料 → 讲稿 → 剧本 → 语音），并新增**讲稿编辑**：可修改各节标题与正文、增删与调整节顺序；讲稿修改后剧本被标记为"基于旧讲稿"，提示重新生成。
- 真实会议详情改为**「概览」与「说话人与音色」两个页签**，主操作按钮随状态切换（合成语音 / n 组待更新 → 重新合成 / 失败重试），一场会议只有一个合成入口。
- **精听改为右侧抽屉**：由播放条上的「精听」按钮打开，始终跟随正在播放的内容，三类内容共用；真实会议的插入 / 修改回答在抽屉中进行。
- 列表项显示**状态标记**（未合成 / 合成中 n/m / 已合成 / n 组待更新 / n 组失败 / 排练所处步骤）与**已听进度**；后台任务进度挂在对应条目上，不再共用一行状态栏。
- 首次使用（全部为空）显示**三张引导卡片**："随便听听 / 准备会议 / 复听会议"；各分区为空时有各自的引导。
- 打开页面时**恢复到上次播放的内容与位置**（停在暂停态，不自动发声）。
- **移除**：全局「生成音频」按钮、「类型」筛选、场景列表中的"排练会议 / 真实会议"项、顶部「真实会议」折叠面板、素材列表上方的「会议材料排练」折叠面板、单行共享状态栏；「来源」筛选降级为公开素材场景标题栏中的下拉（仅多来源时出现）。
- 本变更覆盖 `add-meeting-material-rehearsal`、`fix-real-meeting-audio-and-naming`、`expand-listening-sources-and-sync`、`decouple-speaker-settings-from-baking` 中尚未完成的实机验证项，在新界面上统一验收。

## Capabilities

### New Capabilities

- `listening-practice-workspace`: 听力练习的工作区布局与交互——资料库导航、新建入口、会议条目（多场排练 / 真实会议）的列表与详情、作用域明确的合成入口、讲稿编辑、精听抽屉、条目状态与进度呈现、首次引导与启动恢复。

### Modified Capabilities

（无。既有「会议场景分类的素材库」「精听模式与按需文稿」等需求的行为保持不变：场景仍显示片段数与总时长，精听文稿仍默认不展示、由用户主动打开。）

## Impact

- **代码**：`lib/tools/it_meeting_listening/ui/it_meeting_listening_page.dart`（2179 行单体 State）拆分为外壳 + 各视图组件 + 状态控制器；`real_meeting_panel.dart`、`material_import_panel.dart` 被新的详情视图取代；新增讲稿编辑器、精听抽屉、新建菜单、引导卡片等组件。
- **服务层**：`RehearsalStore` 新增删除一场排练的能力，讲稿保存支持编辑后写回；排练目标时长改为按场保存。
- **依赖**：启动恢复依赖 `fix-listening-resume-position` 提供的全局"上次播放"记录，建议先完成该变更。
- **测试**：`test/it_meeting_listening/page_widget_test.dart`、`real_meeting_ui_test.dart`、`material_import_panel_test.dart` 需随新组件重写。
- **无外部依赖变化**；磁盘数据格式兼容（排练与真实会议的既有数据直接出现在新列表中）。
