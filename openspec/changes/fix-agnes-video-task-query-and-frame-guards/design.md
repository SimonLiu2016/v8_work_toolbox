## Context

动机与行为契约见 proposal.md 与 specs/。此处只记影响实现方式的现状与约束。

**全部结论来自真实 API Key 实测**（非文档推断），见下：

| 项 | 文档说 | 实测 |
|---|---|---|
| 状态取值域 | queued / in_progress / completed / failed | 还有第五态 `pending`（在 `started_at` 之前、`progress=0`） |
| 限流响应 | 未说明 | **HTTP 200 + `{"error":{"code":429,...}}`**，约 25% 概率（1 秒间隔轮询下） |
| 查询 URL 字段 | 主路径顶层 | 主路径 `/agnesapi` 顶层；兜底路径 `/v1/videos/<id>` 在 `metadata.url` |
| 首帧尺寸 | 256–5760 像素 | 确认；1×1 测试图被拒，错误指向 `first_frame` 参数 |
| `video_id` | "查询要用 video_id" | 实测 `id` == `video_id` == `task_id`，三者相同 |
| 云端 URL 时效 | `expires_at` 字段存在 | 实测为 null，十分钟前完成的任务仍可下载 |

**代码现状**（`video_gen_adapter.dart` 的 `AgnesVideoAdapter`）：
- `_queryTask` 只判 `statusCode == 200`，通过后把整个响应当业务体解析。
- `_pollUntilDone` 读顶层 `status` / `progress` / `url`，主路径与兜底路径**共用这一套读取**。
- 阶段切换判定：`if (status == 'in_progress' || status == 'processing') sawInProgress = true;`
- `_prepareKeyframeDataUri` 只压缩大图（>720×1280），不放过小图。

**约束**：
- `_queryTask` 被主路径与兜底路径共用，修正必须让两条路径**各自解析**，而不是继续共用一套顶层读取。
- 不改变 `VideoGenAdapter` 接口签名。
- 不改动 `SenseAudioVideoAdapter` / `KlingVideoAdapter` 的任何行为——它们的响应形态不同。

## Goals / Non-Goals

**Goals:**
- 三条积分损失路径全部堵上：伪成功的限流体、兜底路径读不出 URL、小首帧被拒且报错难懂。
- 阶段判定改用结构化信号（`started_at`），不再依赖状态字符串枚举匹配。
- 实测发现的协议形态写进代码注释，使下一个读代码的人不必重新踩。

**Non-Goals:**
- 不做资产库、不做调用记录补记（那是 `add-studio-asset-library-with-remote-call-ledger` 的范围）。
- 不改轮询间隔的默认值（2 秒实测可用，25% 限流概率来自 1 秒密集查询，不是我们的实际频率）。
- 不为其他供应商（Kling / SenseAudio）做类似修正。

## Decisions

### 决策 1：错误体甄别放在 `_queryTask` 内层，返回类型改为带错误的信封

`_queryTask` 现在返回 `Map<String, dynamic>?`（null = 查询失败）。改为返回一个小信封：

```
_QueryOutcome {
  body,           // 业务响应体（无错误时）
  rateLimited,    // 是否限流
  errorMessage,   // 其他错误的可读信息
  notFound,       // 404：video_id 不存在
}
```

甄别规则：**先看 `body['error']` 是否为非空 Map 或非空字符串**，再看业务字段。命中 `error.code == 429` 或 `error.message` 含限流字样 → `rateLimited`。

备选：只判 HTTP 状态码。否——实测限流返回的是 200，状态码判不出来，这是当前 bug 的根源。
备选：在 `_pollUntilDone` 里判。否——兜底路径也要判，而两条路径的解析即将分离（决策 2），判据放进共用的 `_queryTask` 只有一处。

### 决策 2：两条查询路径各自解析，不再共用顶层读取

主路径 `/agnesapi` 的 `url` 在顶层；兜底路径 `/v1/videos/<id>` 的 `url` 在 `metadata.url`。把 URL 读取拆成两个函数，由知道自己在哪条路径的调用方选择。

兜底路径读不到 URL 时**明确报错**，不返回空串让上层空转——空转是当前最贵的失败模式（烧完整段预算才发现没拿到）。

备选：删掉兜底路径。否——文档说主路径适用所有模式，但万一 Agnes 调整主路径，兜底是仅有的退路。留着，但让它报清晰的错。
备选：两条路径都试读顶层 + metadata。否——那会让"读不到"和"读错了"难以区分，而这两种情况需要不同的用户提示。

### 决策 3：阶段切换改用 `started_at`，状态字符串只用于终态判定

响应有 `started_at`（Unix 秒，排队结束时由空变非空）。以它作为排队→生成的切换信号。

状态字符串**只保留两个用途**：判 `completed`、判 `failed`。其余一切取值（含实测发现的 `pending`、文档外的任何新值）一律视为"还在跑"，继续轮询。

备选：把 `pending` 加进阶段判定。否——枚举匹配是个漏不得的游戏，今天加 `pending`，明天来个 `initializing` 又漏。时间戳是权威的结构化信号。
备选：完全不用状态字符串。否——`completed` / `failed` 仍是最可靠的终态信号，且失败时要从响应里取 `error.message`。

### 决策 4：首帧尺寸守卫放在 `_prepareKeyframeDataUri`，双向处理

当前只压大图。改为：边长 > 上限 → 等比缩小；边长 < 下限（256）→ **明确抛错**并说明"关键帧尺寸过小"。

不把小图放大——放大不增加细节，只会让用户以为图变清晰了，而供应商侧拿到的是一张模糊放大图。拒绝并说明原因比静默放大诚实。

错误信息指明这是本地校验失败、用户该重新生成关键帧，而不是把供应商那条指向 `first_frame` 的错误透出。

备选：放在提交前统一校验。否——`_prepareKeyframeDataUri` 是唯一接触首帧字节的地方，尺寸信息就在那里，放那儿最自然。

### 决策 5：实测协议形态写进代码注释，不作为可执行断言

文档与实测的分歧（第五态、200 限流、两套 URL 位置、URL 不过期）写进 `AgnesVideoAdapter` 的类注释与相关方法的行内注释。

不写成 `assert` 或运行时校验——这些是"我们当时观察到的事实"，不是"永远成立的约束"。供应商改协议时注释会过期，但过期的注释无害；过期的断言会让生产环境抛异常。

## Risks / Trade-offs

- **[错误体甄别规则过宽，把合法响应误判为错误]** → 甄别条件是 `body['error']` 非空。正常任务响应该字段为 `null`（实测确认），不会误判。若供应商某天在正常响应里放非空 `error`，那本身已是异常。
- **[信封类型让 `_queryTask` 的调用方都要改]** → 只有两个调用方（主路径、兜底路径），且都在同一文件内。改动局部。
- **[兜底路径报错会让原本"能空转到成功"的场景变成失败]** → 不存在这种场景——兜底路径读不到 URL 时，主路径也读不到（否则不会走到兜底）。走到兜底又读不到 URL，结果本来就是空转至超时。提前报错只是把失败提前。
- **[首帧拒绝会让原本"供应商可能接受"的请求被挡]** → 下限 256 是供应商的硬校验（实测拒绝过），本地拒绝不会挡掉任何本来能成功的请求。
- **[注释会随供应商演进而过期]** → 接受。注释标注了实测日期与判据，读者能判断是否该重新验证。

## Migration Plan

无数据迁移、无配置变更。改动集中在 `video_gen_adapter.dart` 的 `AgnesVideoAdapter` 与三个既有测试文件的假后端。

实施顺序（按依赖）：
1. 首帧尺寸守卫（独立，最易验证）。
2. 错误体甄别信封（`_queryTask` 改造）。
3. 两条路径各自解析 URL。
4. 阶段判定改 `started_at`。
5. 改测试：按实测形态重写假后端，新增三条针对性用例。

回滚：还原 `video_gen_adapter.dart` 即可；台账与产物文件不受影响。

验证要点：
- 假后端返回 HTTP 200 + `error.code == 429` 时，适配器退避而非静默继续。
- 假后端只实现兜底路径（`metadata.url`）时，适配器能取回视频。
- 假后端返回含 `pending` 且 `started_at` 为空的响应，随后 `started_at` 非空，阶段正确切换。
- 首帧 100×100 时本地拒绝，错误信息含"尺寸过小"。
