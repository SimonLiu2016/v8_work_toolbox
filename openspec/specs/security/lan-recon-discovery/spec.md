# security/lan-recon-discovery Specification

## Purpose
提供在非 Root 权限下高可靠、快速且穿透静默防火墙的局域网存活设备发现能力，确保局域网侦察与渗透测试能完整发现并列出所有接入终端、网关与硬件信息。
## Requirements
### Requirement: 免 Root 链路层 ARP 存活探测与激发
系统在执行局域网主机存活发现时，SHALL 采用非特权应用层网络请求（如 UDP 探测与广播）激发操作系统内核在数据链路层自动发起 ARP 广播查询，迫使目标子网内所有存活设备响应硬件 ARP 应答并刷新操作系统 ARP 缓存。

#### Scenario: 探测包含静默防火墙终端的局域网
- **WHEN** 用户对目标网段（如 192.168.1.0/24）发起局域网侦察，且局域网中存在未开启 Web 服务、静默丢弃 TCP 80/443 的移动设备或电脑
- **THEN** 系统发送轻量激发数据包，触发链路层 ARP 解析，而绝不因目标主机关闭 80/443 端口将其判定为离线

### Requirement: 系统原生 ARP 缓存解析与 MAC/OUI 厂商提取
系统 SHALL 支持读取操作系统原生内核 ARP 缓存表（`arp -a` / `arp -an`），精确提取目标网段内所有活跃设备的 IP 地址、MAC 物理地址以及对应的 OUI 硬件厂商名称，并入库保存为资产元数据。

#### Scenario: 成功提取所有存活设备的硬件信息
- **WHEN** 存活发现阶段执行完毕
- **THEN** 系统解析得到的存活设备列表包含路由器网关及所有真实连接的局域网设备，且每个设备元数据中正确填充真实 MAC 地址与推断出的厂商名称（而非全为 null）

### Requirement: 存活发现优雅降级与日志透传
系统在执行局域网存活发现时，SHALL 优先使用免特权内核 ARP 激发提取方案；若调用外部工具（如 arp-scan 或 nmap），系统 SHALL 在日志面板清晰展示实际探测手段，并透明捕获错误信息，严禁静默吞掉权限异常。

#### Scenario: 非特权环境下 arp-scan 权限受限
- **WHEN** 宿主系统安装了 `arp-scan` 但当前进程无权访问 `/dev/bpf` 设备
- **THEN** 系统自动平滑切换至免特权内核 ARP 与系统 ARP 缓存解析方案，并在日志中记录说明，确保扫描不受阻塞且能完整获取所有设备
