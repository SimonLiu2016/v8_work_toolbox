# security/recon-and-session-management Specification

## Purpose
规范安全测试侦察资产的高性能分页与缓存渲染机制、侦察视图跨会话生命周期同步，以及全局会话管理与原子级极速删除。
## Requirements
### Requirement: 侦察资产海量数据分页与极速响应
系统 SHALL 在 Web 侦察与 LAN 侦察资产列表中采用分页虚拟切片机制（默认每页 50 条），并在资产数据模型中缓存 JSON 解析结果，杜绝在大规模资产（数千至数万条）场景下阻塞主 UI 线程。

#### Scenario: 数千条资产进入侦察面板不阻塞 UI
- **WHEN** 当前会话包含数千条（例如 3,000~4,000+ 条）侦察资产，用户切换或点击进入“侦察”菜单
- **THEN** 系统在第一帧仅渲染当前第 1 页的资产项目（50 条），界面流畅加载不产生任何卡死或 macOS 旋转彩球

#### Scenario: 资产分页翻页与筛选联动
- **WHEN** 用户使用状态或技术栈过滤器筛选资产，或点击上一页/下一页/页码切换
- **THEN** 分页指示栏实时更新“第 X/Y 页 · 共 N 条资产”，并即刻切换显示对应页码内的资产列表

### Requirement: 侦察视图跨会话生命周期严格隔离
系统 SHALL 保证在顶部切换会话时，侦察视图与当前会话的目标范围（Web 域名或 LAN 网段）与资产列表严格绑定，严禁不同会话间复用未重置的输入控制器与陈旧视图状态。

#### Scenario: 切换 Web 会话时域名输入框与资产列表完全同步
- **WHEN** 用户从配置了 `baidu.com` 的 Web 会话切换到配置了 `https://91porn.com` 的 Web 会话
- **THEN** 侦察界面的“根域名”输入框立即更新为 `https://91porn.com`，下方资产列表完全展示该新会话对应的资产

### Requirement: 全局会话快捷管理与秒级级联删除
系统 SHALL 在常用交互区域（顶部会话工具条与切换下拉菜单）提供直观的会话删除入口；底层删除操作 SHALL 采用单条批量 SQL 事务执行，在毫秒级时间内清理会话及其关联的所有资产、发现物与事件；若被删除的会话为当前活跃会话，系统 SHALL 自动回退激活剩余的下一个有效会话。

#### Scenario: 从顶部下拉菜单或顶部栏快捷删除会话
- **WHEN** 用户在顶部会话下拉菜单中点击指定会话右侧的删除图标并确认
- **THEN** 系统在 100 毫秒内彻底清理该会话及其包含的数千条关联数据，并从下拉列表中移除

#### Scenario: 删除当前活跃会话后自动切换到剩余会话
- **WHEN** 用户删除了当前正处于活跃状态的会话，且系统中仍存在其他历史会话
- **THEN** 系统自动将剩余列表中的第一个会话置为当前活跃会话并刷新主视图，避免界面处于空白无会话状态
