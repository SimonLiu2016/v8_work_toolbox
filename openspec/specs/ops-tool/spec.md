## Requirements
### Requirement: 报告中心历史报告删除需二次确认与交互反馈

系统 SHALL 在用户点击历史报告列表项的删除操作时，提供破坏性操作的二次确认弹窗与明确的执行反馈，禁止静默物理删除。

#### Scenario: 弹出删除确认对话框
- **WHEN** 用户在报告中心左侧列表点击某份历史报告的删除图标
- **THEN** 系统 MUST 弹出包含该报告标题的确认对话框，告知该删除操作无法撤销
- **AND** 若用户点击取消，系统 MUST NOT 触发数据库删除，界面保持不变

#### Scenario: 确认删除后弹出提示反馈
- **WHEN** 用户在删除确认对话框中点击确定
- **THEN** 系统从数据库物理删除该份报告
- **AND** 系统通过底部 SnackBar 提示「报告已删除」

### Requirement: 删除报告后的选区退避与界面状态同步

系统 SHALL 在删除操作后正确同步左侧列表与右侧编辑/预览区的状态，防止已删除报告内容悬挂或选区丢失。

#### Scenario: 删除当前正在查看的唯一报告
- **WHEN** 历史报告列表中仅有 1 份报告且用户确认将其删除
- **THEN** 系统清空列表并展示「暂无历史报告」
- **AND** 系统将当前报告引用置空，清空标题与内容输入框，右侧区域展示「请选择或新建一份报告」空状态占位

#### Scenario: 删除当前正在查看的非唯一报告
- **WHEN** 历史报告列表中有多个报告，且用户删除了当前正在编辑或查看的报告
- **THEN** 系统自动将选区切换到剩余报告的第一项，并将右侧编辑区与预览区同步更新为该报告的标题与内容

#### Scenario: 删除未选中的其他报告
- **WHEN** 用户删除了历史列表中非当前选中的报告
- **THEN** 系统从列表中移除该项，右侧正在编辑的当前报告标题、内容与未保存修改保持不变

#### Scenario: 释放 Excel 生成跳转的初始报告挂载态
- **WHEN** 用户通过 Excel 模板生成报告并跳转至报告中心，随后执行了保存或删除操作
- **THEN** 系统释放初始挂载报告态，后续列表刷新或删除操作 MUST NOT 将当前选区强制还原为最初由 Excel 传入的对象

### Requirement: 报告 Markdown 正文内容持久化与还原

系统 SHALL 保证报告的 Markdown 内容或分节能够在本地数据库完整持久化，并在重新选中历史报告时完整恢复至编辑器与预览区。

#### Scenario: 保存并重新加载报告内容
- **WHEN** 用户在报告中心编写并保存报告，之后在左侧列表中重新点击该报告
- **THEN** 系统从数据库完整读取其 Markdown 正文内容并回填至文本控制器，Markdown 预览区正确渲染相应内容，不得出现内容变为空白

### Requirement: 运维小工具入口与多窗口生命周期
系统 SHALL 在主启动器中注册「磐石运维工具」，且支持在独立的桌面子窗口中以深色卡片风格完整渲染多标签控制台。

#### Scenario: 独立窗口呼出
- **WHEN** 用户在主工具箱列表中点击「磐石运维工具」或按下回车
- **THEN** 系统呼出尺寸为 1200x800 的独立桌面窗口，展示侧边栏导航与仪表盘概览，且主进程环境与代理/AI配置同步生效

### Requirement: DevOps GitLab 项目管理与批量操作
系统 SHALL 允许用户配置 GitLab 连接，按 Group 检索项目列表，并支持跨项目批量创建分支与批量递增 pom.xml 版本号。

#### Scenario: 批量创建分支
- **WHEN** 用户勾选多个 GitLab 项目并输入源分支与新分支名称执行创建
- **THEN** 系统并发调用 GitLab API 创建对应分支，并在操作日志中反馈每个项目的创建成功或失败详情

#### Scenario: 批量更新 pom.xml 版本
- **WHEN** 用户勾选多个 Maven 项目并指定目标版本号及 Commit Message 执行更新
- **THEN** 系统读取项目根目录下的 pom.xml，定位并修改版本字段后向目标分支提交 commit

### Requirement: DevOps Jenkins 构建触发与状态追踪
系统 SHALL 允许用户配置 Jenkins 连接，支持自动获取 CSRF Crumb 并对选定项目发起参数化构建与状态追踪。

#### Scenario: 触发 Jenkins 构建
- **WHEN** 用户为选定项目选择构建分支及参数后点击触发构建
- **THEN** 系统携带 Crumb 发起构建请求，并展示轮询到的构建状态（排队中/构建中/成功/失败）

### Requirement: DevOps ArgoCD 镜像标签监控与防漂移锁定
系统 SHALL 支持按环境管理 GitLab 配置仓中的镜像 Tag 配置，提供可编辑的 Tag 配置表，并在后台按环境配置的间隔持续巡检、比对与告警。`argocd_tags` 是用户维护的配置表：`target_tag` 由用户写入，`current_tag` 由扫描与巡检写入，二者语义不得互换。配置仓目录下每个 `values-<服务名>.yaml` 文件对应一个微服务，其中的 `Image`/`Tag` 字段值即该服务的镜像 Tag；系统 SHALL 以服务名为行展示，不得将非服务文件或目录当作微服务。

#### Scenario: 编辑环境的入口唯一
- **WHEN** 用户需要修改已存在的监控环境
- **THEN** 系统 SHALL 通过环境条中带「编辑环境」文字的按钮打开编辑弹窗
- **AND** 环境 SHALL 在单行条内同时展示名称、模式、信息概要与编辑/启停/删除操作，不得分成两个独立区块

#### Scenario: Tag 配置表列宽随窗口弹性缩放
- **WHEN** 用户调整运维工具窗口宽度
- **THEN** Tag 配置表的项目名、当前 Tag、目标 Tag 三列 SHALL 弹性缩放
- **AND** 关闭弹窗提醒、状态、启用三列 SHALL 保持内容固有宽度

#### Scenario: 刷新 Tag 并与已有配置合并
- **WHEN** 用户选中环境后点击「刷新 Tag」
- **THEN** 系统列举配置仓内全部以 `values-` 前缀开头的 `.yaml` / `.yml` 文件，按项目名与已有配置合并（保留已填的目标 Tag、关闭提醒开关与启用状态），写回配置表并在界面展示「已刷新 N 个 Tag」
- **AND** 系统 MUST NOT 将 `Chart.yaml`、`.gitlab-ci.yml` 等非服务文件或目录条目纳入列表
- **AND** 若文件数超过单页上限，系统 SHALL 通过 `Link: rel="next"` 逐页翻完，不得静默截断
- **AND** 列举请求 SHALL 携带配置仓路径中解析出的子目录与分支，不得退化为列举仓库根目录
- **AND** 若存在读取失败的文件，系统 SHALL 在界面同时展示成功数与失败数，不得静默丢弃

#### Scenario: 列举请求可诊断
- **WHEN** 系统以 debug 模式列举配置仓目录
- **THEN** 系统 SHALL 输出本次请求的 URL、HTTP 状态码、本页条目数与 `Link` 响应头
- **AND** 当列举结果中不含任何 `values-` 前缀文件且请求未限定子目录时，系统 SHALL 给出「列举请求未限定子目录」的错误提示，而非提示用户检查其配置的路径

#### Scenario: 新增与编辑监控环境
- **WHEN** 用户新建或编辑监控环境并填写环境名称、GitLab URL、用户名、密码、Token（可选）、配置仓路径、监控模式与检查频率
- **THEN** 系统保存环境配置并支持随时修改、启停与删除；启用状态为启用的环境才会纳入后台巡检
- **AND** 环境必须至少配置一种可用于访问配置仓的凭据（密码或 Personal Access Token），两者皆空时系统 SHALL 拒绝保存

#### Scenario: 从服务文件提取镜像 Tag
- **WHEN** 系统读取某个 `values-<服务名>.yaml` 文件内容
- **THEN** 系统 SHALL 取其 `image` 段下的 `tag` 值作为当前 Tag，并去除该值两端成对的引号
- **AND** 文件中不存在可识别的 `tag` 时，该行的当前 Tag MUST 呈现为空而非猜测值

#### Scenario: 批量设定目标 Tag
- **WHEN** 用户点击「复制当前到目标」
- **THEN** 系统将配置表中每一行的当前 Tag 写入该行的目标 Tag，作为后续比对的基准值

#### Scenario: 逐行编辑与保存 Tag 配置
- **WHEN** 用户在目标 Tag 列内联修改、切换「关闭弹窗提醒」或「是否启用」后点击「保存 Tag 配置」
- **THEN** 系统将配置表整体持久化，并提示「Tag 配置已保存」

#### Scenario: 后台巡检与不一致提示
- **WHEN** 后台巡检按启用环境中最小的检查间隔触发，发现某项目当前 Tag 与目标 Tag 不一致且该行未被关闭提醒与未被停用
- **THEN** 系统将该行标记为不一致状态并在界面高亮提醒，同时通过操作系统原生通知弹出变更消息，并仅更新该行的当前 Tag 与最后检查时间而不改动用户填写的目标 Tag

#### Scenario: 监控模式仅告警
- **WHEN** 环境处于监控模式且检测到 Tag 偏离
- **THEN** 系统仅记录告警日志并通知提醒，不修改配置仓中的任何文件

#### Scenario: 锁定模式自动回写
- **WHEN** 环境处于锁定模式且检测到 Tag 偏离
- **THEN** 系统自动向配置仓提交修复 Commit 将 Tag 恢复为目标值，记录修复日志并在通知中标注「已自动修复」

#### Scenario: 关闭提醒的环境仍更新数据
- **WHEN** 某项目被标记为关闭弹窗提醒，巡检发现其 Tag 偏离
- **THEN** 系统跳过通知但仍更新该行的当前 Tag，保持数据实时性

### Requirement: 多源数据采集与 SQL 模板
系统 SHALL 支持配置 PingCode、Grafana 及数据库 (PhpMyAdmin/SQL) 数据源，并提供可复用的 SQL 查询模板及测试执行。

#### Scenario: 执行数据源查询
- **WHEN** 用户选择已保存的数据源并执行查询或测试连接
- **THEN** 系统通过安全 HTTP 会话获取响应，并以表格形式实时呈现查询结果数据

### Requirement: Excel 文件解析与模板引擎渲染
系统 SHALL 支持解析本地 Excel 文件（多 Sheet），并根据预设抽取规则（单元格引用、列统计聚合、数据库结果填充）将数据渲染为格式化报告。

#### Scenario: 根据模板渲染生成报告
- **WHEN** 用户导入包含多 Sheet 的 Excel 文件并选择报告模板执行生成
- **THEN** 系统解析单元格和聚合公式，自动替换模板占位符生成完整的 Markdown 分节内容

### Requirement: 报告中心与 HTML 邮件导出
系统 SHALL 提供 Markdown 报告编辑、分节管理（销售总览、服务自动化、异常告警等）及一键渲染为 HTML 邮件格式。

#### Scenario: 导出为邮件 HTML
- **WHEN** 用户在报告中心点击导出或准备发送邮件
- **THEN** 系统将 Markdown 转换为带内联样式的排版精美 HTML 邮件正文并流转至邮件模块

### Requirement: 邮件账户管理与 SMTP 发信
系统 SHALL 支持配置多个 SMTP 账户（支持 TLS 加密）及通讯录分组，并可直接投递生成的 HTML 报告邮件。

#### Scenario: 测试与发送报告邮件
- **WHEN** 用户选择发件账户、勾选收件人分组并点击发送
- **THEN** 系统建立 SMTP TLS 连接完成邮件投递，并提示发信成功及记录发信流水

### Requirement: 定时任务调度与执行日志
系统 SHALL 支持基于 Cron 表达式在后台定时执行数据拉取、报告生成及邮件自动分发，并持久化记录每次执行的状态与耗时。

#### Scenario: 定时任务触发执行
- **WHEN** 系统后台调度时钟匹配定时任务的 Cron 表达式
- **THEN** 系统自动串行执行抓取、生成与发信流程，并将执行结果写入任务日志表

### Requirement: 接入宿主全局 AI 研判与生成
系统 SHALL 直接复用宿主全局统一的 AI 供应商配置（AiConfigStore 与 AiService），对报告异常指标研判、提炼总结和智能问答。

#### Scenario: 报告异常智能研判
- **WHEN** 用户在报告分节中点击「AI 研判」或生成摘要
- **THEN** 系统读取当前宿主默认启用的文本模型与配置发起流式/完整生成，将研判结论无缝插入报告，无需用户额外配置 API Key

### Requirement: ArgoCD 监控环境的管理入口可发现且破坏性操作需确认

系统 SHALL 让用户在不依赖图标猜测的前提下发现并执行 ArgoCD 监控环境的新建、编辑、启停与删除，且删除这一破坏性操作 MUST 经二次确认后执行。

#### Scenario: 通过显式入口编辑环境

- **WHEN** 用户选中某个 ArgoCD 监控环境
- **THEN** 系统在环境详情区提供一个带「编辑环境」文字的按钮，点击后弹出回填该环境当前配置的编辑弹窗
- **AND** 环境标签上的铅笔图标 MUST 具备 tooltip 说明其作用为编辑，不得以无标签的裸图标作为唯一编辑入口

#### Scenario: 删除环境前要求确认

- **WHEN** 用户对已存在的 ArgoCD 监控环境触发删除
- **THEN** 系统 MUST 弹出确认对话框，明示该操作将同时清除其名下全部 Tag 配置行
- **AND** 仅在用户确认后执行删除，取消则不产生任何数据变更

#### Scenario: 凭据为空的环境不允许启用

- **WHEN** 用户保存一个既未填写 GitLab 密码也未填写 Personal Access Token 的 ArgoCD 监控环境，或将「启用」开关打开
- **THEN** 系统 MUST 拒绝保存并提示缺少可用于访问配置仓的凭据
- **AND** 该环境不得进入后台巡检的启用集合

### Requirement: 凭据字段默认脱敏且支持临时显示明文

系统 SHALL 对运维工具内全部敏感凭据输入框默认脱敏显示，并提供一键在脱敏与明文之间切换的入口；明文状态 MUST 为临时态，不得在弹窗关闭或路由切换后仍然保留。

#### Scenario: 凭据默认脱敏

- **WHEN** 用户打开任意包含凭据的配置弹窗（DevOps 连接、ArgoCD 监控环境、邮件账户、数据源）
- **THEN** 密码、API Token、Personal Access Token 与邮箱授权码字段 MUST 以脱敏形式呈现，不明文常显

#### Scenario: 切换显示明文

- **WHEN** 用户点击凭据字段的显示/隐藏按钮
- **THEN** 该字段在脱敏与明文之间切换，且按钮图标与 tooltip 同步反映切换后的下一次点击语义

#### Scenario: 明文态不跨会话保留

- **WHEN** 用户将某凭据字段切为明文后关闭该弹窗，或切换到运维工具的其他视图再返回
- **THEN** 该字段 MUST 恢复为脱敏状态

### Requirement: 编辑既有凭据时留空表示保持原值

系统 SHALL 在编辑已保存的 DevOps 连接与 ArgoCD 监控环境时，不将数据库中已存储的密码与 Token 回填进输入框，并以「留空即保持原值不变」作为保存语义。

#### Scenario: 编辑弹窗不回填已存凭据

- **WHEN** 用户打开一个已保存的 DevOps 连接或 ArgoCD 监控环境的编辑弹窗
- **THEN** 密码与 Token 输入框 MUST 为空，并以辅助文案说明留空则保持原有凭据不变
- **AND** 系统 MUST NOT 在界面上暴露已存储凭据的内容

#### Scenario: 留空保存不破坏既有凭据

- **WHEN** 用户在编辑弹窗中仅修改非凭据字段（如名称、频率、路径）而将密码与 Token 留空，并执行保存
- **THEN** 系统 MUST 保留该条配置原有的密码与 Token，仅更新被修改的字段

#### Scenario: 填写凭据则覆盖

- **WHEN** 用户在编辑弹窗的密码或 Token 字段中输入了新值并保存
- **THEN** 系统 MUST 以新值替换该条配置原有的对应凭据
